- (constraint) Inherited from PRD draft + memory: Frappe v16 only; pure Python; graphql-core; planner preloads batches then executes prebuilt result graph; single DataAdapter; all reads via _authorized_query (frappe.qb get_query, ignore_permissions=False); DocWeave Settings Single DocType exposure, nothing exposed by default; signed user/filter-bound cursor on last scanned candidate, short pages, scan budget; masked -> null + MASKED error; reads AND writes; MCP secondary (introspection, depth/cost limits, descriptions, SDL export), no MCP server
- (question) Open from PRD: does frappe.qb apply masking vs only get_list; mutation scope; subscriptions/uploads; child retrieval strategy; HTTP integration/auth; schema build/cache strategy; tooling/test stack
- (direction) User asked to 'do the architecture' end to end: fast path, draft whole spine with [ASSUMPTION] tags
- (event) Verified frappe version-16 source: Engine.get_query ignore_permissions=True default; masking metadata attached only when apply_permissions; execution calls mask_fields with get_masked_fields(parenttype). Resolves PRD qb-masking question at source level; runtime test still required
- (version) Frappe v16 requires-python >=3.14,<3.15; graphql-core 3.3.0 (2026-09-27, >2wk old) chosen over 3.2.7; frappe-bench 5.31.1; ruff 0.17.2
- (decision) Paradigm hexagonal: api -> schema/execution -> adapter port -> Frappe. Only docweave/adapter imports frappe.qb/db/get_all/get_list/get_doc for data. Prevents scattered permission-bypassing data paths
- (decision) Two-phase execution: validate -> plan from AST -> preload batches via adapter -> build result graph -> graphql-core executes with default dict resolvers; no resolver performs I/O. Prevents N+1
- (decision) Candidates = SQL with Frappe permissions applied (roles, user perms, permission_query_conditions); then document-level has_permission per row in Python; scan budget counts SQL candidates
- (decision) Masking: adapter returns per-row masked-field set from meta.get_masked_fields(parenttype) + user perms, value replaced by MASKED sentinel; resolver raises GraphQLError code MASKED. Filter/sort on masked or non-permitted fields rejected (prevents oracle leaks)
- (decision) Schema user-independent, per site, cached in frappe.cache keyed by site+schema_revision; revision bumped after commit on DocWeave Settings, DocType, Custom Field, Property Setter changes
- (decision) Naming: DocType -> PascalCase type; fieldname -> camelCase; Link field x -> x: String (raw name) + xDoc: Type; child table -> list; roots: salesOrder(name), salesOrders(filter, orderBy, first, after) connection; mutations createX/updateX/deleteX
- (decision) Writes via Frappe Document API in adapter (insert/save/delete, never ignore_permissions); one mutation field per request transaction; v1 create/update/delete; submit/cancel deferred [ASSUMPTION]
- (decision) Cursor: keyset on (order field, name); payload {v, doctype, filter_hash, user, order, last_key} HMAC-SHA256 with site-derived key, base64url; mismatch -> BAD_CURSOR
- (decision) Error codes fixed enum: MASKED FORBIDDEN NOT_FOUND NOT_EXPOSED VALIDATION BAD_CURSOR DEPTH_LIMIT COST_LIMIT INTERNAL; no tracebacks to clients
- (decision) Transport: single whitelisted POST endpoint docweave.api.graphql, no guests; Frappe native auth (session+CSRF, API key/secret token, OAuth bearer); introspection for authenticated users
- (decision) Linked docs authorized independently; unauthorized link -> null + FORBIDDEN. Child rows fetched only for authorized parents with parent_doctype set
- (decision) Boundary enforcement: AST boundary test in test suite forbidding data-access calls outside docweave/adapter, plus integration tests on ERPNext v16 (test-only dependency; core app does not depend on ERPNext)
- (decision) Deployment: standard Frappe app (bench get-app/install-app), runs inside Frappe web workers, no extra services; DB MariaDB (Frappe default), Postgres deferred; CI GitHub Actions with MariaDB+Redis services
